# Bounded control-backup boundary probes

The multipart control backup checks for legacy keys above each configured
prefix's normal `zzzz` capture boundary. An empty upper tail previously made
PostgreSQL scan later unrelated namespaces until its five-second timeout.
A failed snapshot never advanced backup health or removed source data.

The probe now has an enclosing upper index bound, using the verified letter
successor already used by diagnostic retention. Incrementing the trailing
slash is unsafe under English punctuation ordering. Before probing, the
backup checks the actual column collation and refuses unverified locales.
Both capture paths keep their existing repeatable-read, read-only snapshot,
size limits, full R2 readback, and fail-closed handling of hidden keys.

Tests cover unknown-collation rejection, snapshot/spool failure behavior,
ordinary controls, and high suffixes across every configured control prefix
in disposable PostgreSQL. No schema, grants, runtime flags, strategy settings
or service placement changes are included.

Deploy with the existing holds intact and rerun the bounded multipart backup
from an authorized private shell. A verified control snapshot is limited to
its documented scope; it does not certify complete financial history,
settlement outcomes, physical disk headroom or permission to restart trading.
